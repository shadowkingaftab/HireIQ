# ORIONET

Evidence-first hiring intelligence platform. It helps candidates demonstrate capability through verifiable work and gives recruiters an explainable way to search, compare, assess, and hire talent.

## Features

- Evidence-first candidate profiles
- Skill graph and capability inference
- Explainable candidate-job matching
- Adaptive assessments
- GitHub and resume ingestion
- Team collaboration
- Analytics and reporting

## Quick Start

Run these in two terminals from the repository root. These commands use the
root `backend` and `frontend` folders; `proofhire/` is a separate nested checkout.

```bash
# Terminal 1: backend
pip install -r backend/requirements.txt
uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
```

```bash
# Terminal 2: frontend
cd frontend
npm install
npm run dev
```

If you want to expose the app through ngrok, start the frontend first, then run:

```bash
ngrok http 3000
```

The Vite dev server listens on 0.0.0.0 and accepts ngrok hostnames, so the tunnel can reach the app without the "ERR_NGROK_8012" refusal error.

## Production deployment

For a $0 launch, deploy the frontend to Cloudflare Pages, the FastAPI backend to
Render's free web service, and use Supabase Free for PostgreSQL. The current API
does not require Redis for core requests, so leave `REDIS_URL` unset; caching is
simply unavailable. This avoids creating any paid Render services.

### Cloudflare Pages

Connect the GitHub repository in Workers & Pages and use these build settings:

- Root directory: `frontend`
- Build command: `npm run build`
- Build output directory: `dist`
- Production environment variable: `VITE_API_URL=https://<your-render-service>.onrender.com/api/v1`

`frontend/public/_redirects` keeps direct visits to routes such as `/signup`
working. The production API URL template is in
[`frontend/.env.production.example`](./frontend/.env.production.example).

### Render API and Supabase database

1. Create a Supabase Free project and copy its PostgreSQL connection string.
   Use the Session pooler connection string if the direct connection is
   unreachable from Render. Keep the password private.
2. Create a Render Blueprint from this repository and select
   `backend/render.yaml`. It creates only a free FastAPI web service. When
   prompted, set `DATABASE_URL` to the Supabase connection string; `SECRET_KEY`
   is generated by Render. The service runs migrations when it starts.
3. Copy the service's `onrender.com` URL into Cloudflare Pages as
   `VITE_API_URL=https://<your-render-service>.onrender.com/api/v1`, then
   redeploy the frontend.

Free-tier tradeoffs: Render sleeps after 15 minutes without traffic, and its
first request after sleeping can take about a minute to wake. Supabase Free
includes a 500 MB database but pauses projects after a week of inactivity.
Neither service is a no-downtime production setup; monitor usage and export
database backups yourself. Do not create paid Postgres or Key Value services
for this configuration.

### Domain DNS

To keep DNS hosted at SEUS initially, use `www.orionet.us.mw` as the Pages
custom domain and add the CNAME record Cloudflare Pages provides in SEUS DNS.
Add `api.orionet.us.mw` as a custom domain on the Render service and create the
DNS record Render provides. You can later move the zone to Cloudflare DNS for
apex-domain support; copy existing DNS records before changing nameservers.

The API's public health endpoint is `/health`; after both services are live,
confirm it responds before testing sign-up and sign-in on the custom domain.
